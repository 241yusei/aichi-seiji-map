# 選挙のときの運用手順（知事選・統一地方選・市町村選挙）

中立・非投票誘導はこのサイトの大原則。選挙が近づいたら、この手順だけを淡々と行う。
判断に迷ったら「載せない・止める」を選び、オーナーに確認する。

## 0. 公職選挙法の要点（条文で確認済み）

| 条文 | 内容 | このサイトでの扱い |
|---|---|---|
| 33条 | 任期満了による地方選挙は、任期が終わる日の前30日以内に行う | 投票日の「入りうる期間」だけを示し、日付は予想しない |
| 129条 | 選挙運動ができるのは、立候補の届出の日から投票日の前日まで | 本サイトは選挙運動をしない。特定の候補者・政党への投票を呼びかけない |
| 138条の3 | 当選者を予想する**人気投票の経過・結果を公表してはならない** | アンケート・投票予想・人気ランキング・「支持率」風の表示はつくらない |

出典：[公職選挙法（e-Gov法令検索）](https://laws.e-gov.go.jp/law/325AC1000000100)

## 1. 選挙管理委員会が選挙の期日を発表したら

1. `data/election-windows.json` に追加して、デプロイする。

   ```json
   { "name": "愛知県知事選挙", "from": "（告示日 YYYY-MM-DD）", "until": "（投票日 YYYY-MM-DD）" }
   ```

2. これだけで次が自動で動く（再ビルドは不要）。
   - 告示日〜投票日：サイト全体に「選挙期間中」の注意書き（閲覧時にブラウザが日本時間で判定）
   - 告示日〜投票日：SNS自動投稿の停止（`scripts/buffer_post.py` が同じファイルを読む）
   - 選挙カレンダー・投票ガイドに「投票日まで あと○日」
3. PRに選挙管理委員会の発表URLを必ず書く。

## 2. 告示日（立候補の届け出があったら）

1. 選挙管理委員会が発表した**候補者の届出情報だけ**を `data/candidates.json` に入れる。

   ```json
   {
     "electionId": "aichi-governor-2027",
     "name": "（氏名）", "kana": "（ふりがな）", "age": 0,
     "party": "（党派・届出どおり）", "status": "新人", "occupation": "（職業・届出どおり）",
     "filedAt": "（届出日）", "sourceUrl": "（選挙管理委員会の発表URL）"
   }
   ```

2. 並び順は自動で**五十音順**（選挙公報・掲示板の順とは異なることを画面で明示済み）。
   写真・色・大きさの差はつけない。全員同じ項目。
3. **告示前に報道された「出馬予定者」は載せない。** 届け出で確定した人だけ。
4. `npm run validate`（出典URL・読みがなは必須）→ ビルド → PR。

## 3. 選挙期間中（告示日〜投票日）にしないこと

- 新しい事実カードの公開、SNSでの新規投稿（自動投稿は止まるが、手動でもしない）
- 候補者どうしの比較表・ランキング・「おすすめ」
- 候補者の発言の切り抜きや要約の新規追加（既存の記録の表示は、出典つきの事実として継続してよい）
- 誤りの指摘があれば `/corrections` に記録して、すぐに直す（これは期間中もする）

## 4. 投票日のあと

1. 当選者を議員名簿と首長データに反映する。議員名簿は `data/seed/legislators.*.seed.json` を更新してから再生成（国会 `npm run seed:legislators`、県議会 `npm run fetch:kengikai`、名古屋市会 `npm run fetch:nagoya`、その他の市 `npm run fetch:city`）。首長は `data/executives.json` の `termStart`/`termEnd`。出典は選挙管理委員会の確定発表。
2. 投票率は選挙管理委員会の確定値を `data/history.json` に追加（知事選・名古屋市長選）。
3. `data/election-windows.json` の期間は残してよい（過ぎた期間は自動で無視される）。
4. `/corrections` に「更新」として記録。
