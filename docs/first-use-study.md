# 初回利用テスト計画と記録

作成日：2026-10-23。対象：政治のトリセツ あいち・なごや。

**今回は本人の指示により、協力者を確保せず、テストの準備とAI・自動ブラウザによる操作検証を行う。実参加者テストは未実施・0人で、人による観測結果はない。**
実参加者向けの以下の計画は、将来実施する場合の準備資料。協力者・実施日・実参加者が使う対象ビルドは未確定であり、本PRの操作検証と混同しない。
以下の5枠は募集計画であり、参加した5人の記録ではない。AI・自動ブラウザの確認は人による初回利用テストの人数・成功数へ加えない。

## 確かめること

1. トップから指定地域へ進み、代表者の氏名と国・県・市町村の層を説明できるか。
2. 代表者を確認した後に、具体的な暮らしの制度・計画へ移れるか。
3. 対象者・対象地域と、決まったこと／未確認のことを区別できるか。
4. 解説の根拠となる公式資料を開き、発行主体を確認できるか。

現行導線は、名古屋市では区から国・県・市の議員へ、それ以外の市町村では首長・市町村議員の一覧へ進む。暮らしの3テーマはトップから直接開くこともできる。決められた順番を再現したかではなく、目的を達成できたかを観察する。

## 募集と実施条件

- サイトを使ったことがない、愛知の地域情報を調べる可能性がある成人5人を想定する。制作者・開発協力者は本調査の対象に含めず、予備確認として分ける。
- 政治への関心の強弱、スマートフォンに慣れた人／操作に不安がある人が偏らないよう募集する。政治的意見、支持政党、投票先、具体的な居住地は聞かない。
- 目安はスマートフォン4枠・PC1枠。可能ならキーボードや支援技術を使う人を含め、利用する支援を妨げない。5枠で条件を満たせなかった場合は、欠けた条件を結果に明記する。
- 利用環境・端末区分・入力方法だけ記録する。氏名、連絡先、住所、郵便番号、政党への態度を研究記録へ入れない。募集連絡先が必要な場合は、ユーザー側で調査記録と分けて管理する。本計画の作成だけで募集連絡や招待は送信しない。
- 参加前に目的、任意参加、中断・回答拒否が可能なこと、記録範囲を説明し同意を確認する。画面録画・音声録音は標準では行わず、必要なら目的と保管・削除方法を先に示して別途同意を得る。
- 一人20〜30分を確保する。謝礼、外部サービス契約、謝礼の支払いはこの計画には含めない。
- 原則は公開前の同一プレビュービルドで行う。端末の初期状態は地域未保存。保存地域が残る場合は、本人が同意したうえで当該サイトの保存だけ解除する。個人のブラウザ全体を消去しない。
- テスト用プレビュー・localhostでは利用計測を無効にする。本番で行う場合も、操作開始前に測定除外を設定する（方法は `usage-measurement.md`）。

## 参加者へ読み上げる説明

> 今日はサイトの分かりやすさを調べます。あなたを試すものではありません。正解の操作は決めていません。迷った点や、今考えていることを、できる範囲で口に出してください。途中でやめても、答えたくない質問を飛ばしても大丈夫です。実際の申込み・支払い・問い合わせは行いません。

タスクは一つずつ読み、次のタスクや完了基準を先に見せない。「地域を見る」「暮らしの3テーマ」「出典」などの画面上のラベルや、押す場所は教えない。

### T1：代表者を調べる

> ［調査用の地域］について調べることになりました。このサイトを使い、この地域を担当する代表者のうち一人の名前と、どの議会・行政の層の人かを教えてください。

氏名・層を確認したら、同じ画面状態を維持してT2へ進む。トップへ戻してやり直させず、戻る・検索・メニューなどは本人が選べるようにする。

### T2：暮らしに関わる具体案件を調べる

割当案件に合わせ、次のうち一つを読む。T1の地域の制度が自動で選ばれているとは説明しない。

- 通園支援：「次は名古屋市の制度を調べます。保育施設へ定期的に通っていない小さな子が利用できる支援について、対象と利用の条件、費用について分かること・別に確認が必要なことを教えてください。」
- 公共交通：「次は愛知県の公共交通を調べます。通院や通学の移動を支える計画について、誰に関わる計画か、既に決まっていることと、個別に確認が必要なことを教えてください。」
- 防災：「次は愛知県の防災を調べます。防災計画で何が更新されたか、誰の対応に関わるか、費用や実施状況について分かること・まだ確認が必要なことを教えてください。」

### T3：根拠資料を確かめる

> 今説明した内容を、このサイトの説明以外の元資料で確かめたいと思います。根拠となる公的な資料を開き、どの機関が出した資料か教えてください。

外部資料に到達したら終了する。行政サービスへの実申請や外部アカウントへのログインは不要。

## 観察手順と支援の扱い

1. 司会役はタスクを読み、操作開始から計時する。記録役は時刻・段階・事実を記録する。対象ビルド、端末区分、タスク割当、計測除外を開始前に控える。
2. 通常は黙って観察する。「分かりましたか」「そこではありません」などの評価・誘導をしない。必要なら「今、何を探していますか」と聞き、行き先やラベルを示さない。
3. 同じ場所の往復、目的と異なる画面の反復、本人の「分からない」の発言を迷いとして記録する。30秒の停止だけで失敗にしない。読み取り中か迷いかを観察する。
4. 支援は `H0 なし`、`H1 目的の再読み上げ・中立な確認`、`H2 場所や進路のヒント`、`H3 操作代行` に分け、内容と時刻を記録する。H1後の完了は「中立支援あり」、H2/H3後は「誘導・代行あり」とし、無支援成功へ数えない。
5. 一タスク5分、明確な断念、本人の中止希望のいずれかで区切る。5分は調査上の上限で、利用者の能力や製品性能の基準ではない。
6. 前のタスクで行き詰まっても、失敗を記録して次のタスクを行える。司会者が次の開始画面まで案内した場合は「開始位置の支援あり」とし、連続導線の無支援完了には数えない。
7. 途中で政策への賛否が出ても掘り下げず、発見・理解・出典への到達という操作へ戻す。本人の政治的発言は記録しない。
8. 終了後に「どこで迷いましたか」「どの情報を根拠にそう考えましたか」と確認する。使いやすかったという感想だけで完了・理解を判定しない。

テスト実施日に公式資料と対象ビルドを再確認し、以下の採点メモを更新する。人物名や制度条件が変わった場合、古いメモを正解として使わない。

| タスク | 完了の条件 | 完了とみなさない状態 |
|---|---|---|
| T1 | 指定地域に対応する代表者一人の氏名と、その人の国・県・市町村の層を、自分の言葉で答える。議員と首長を選んだ場合の違いも確認する | 一覧を表示しただけ、別地域の人物、層を取り違えたまま終了 |
| T2・通園 | 名古屋市の制度であること、年齢・保育所等へ通っていない条件、料金は施設別で実費等の確認が必要なことを区別する | 豊田市にも同じ条件で使えると断定、誰でも無料と説明、制度名を開いただけ |
| T2・交通 | 県の2024〜2026年度計画と個別路線の運行を区別し、関係する利用者と、路線別運賃・補助額等の未確認点を説明する | 計画の存在を全路線の存続・増便・無料化の決定と解釈 |
| T2・防災 | 県計画の更新と、個別の設備工事・予算・市町村での反映を区別し、対応主体と未確認点を説明する | 計画修正だけで全対策・工事の完了や安全が保証されたと解釈 |
| T3 | T2の記述に関係する行政機関の公式資料を開き、発行主体と、どの記述の根拠かを示せる | サイト内の出典一覧を表示しただけ、無関係の公式トップ、リンクを押したが到達確認できない |

通園の具体条件は、作成時点のブリーフでは生後6か月〜3歳未満、保育所等に通っていない子、月10時間が記載されている。これは採点準備用で、実施日の制度を保証するものではない。

## 匿名記録テンプレート

実参加者を募集して実施した時に限り `P01` などを付ける。AI・自動確認には `A01`、制作者の予備確認には `D01` を付けて別表に残す。氏名・居住地域・閲覧した人物名・政党名・関心テーマの自由記述は保存しない。以下の案件名は割り当てた固定シナリオの管理用で、本人の政治的関心ではない。

```text
記録種別：実参加者 / 制作者の予備確認 / AI・自動確認
匿名記録番号：
実施日：
対象ビルド / 端末区分 / 入力方法：
タスク割当：計画表の枠番号（本人の居住地は記録しない）
計測除外の確認方法：
タスク：T1 / T2 / T3
開始 / 終了 / 経過秒：
結果：完了 / 部分完了 / 断念 / 時間上限 / 外部資料の接続失敗 / 中止
支援：H0 / H1 / H2 / H3、内容と時刻
迷い：時刻、段階、往復・停止・誤認などの観察事実
完了根拠：氏名と層の照合OK / 対象と条件の説明OK / 関係する公式資料と発行主体の確認OK
対象・地域・未確認事項の取り違え：なし / あり（政治的意見や固有名は書かず内容を要約）
改善候補：観察事実と結び付けて記録
次タスクの開始位置に司会者の案内：なし / あり
```

| 実参加者番号 | T1 秒・結果・支援 | T2 秒・結果・支援 | T3 秒・結果・支援 | 迷い・取り違え | 実施状態 |
|---|---|---|---|---|---|
| 未割当 | — | — | — | — | 実参加者テスト未実施 |

時間は完了・部分完了・時間上限などの結果と組にして記録する。成功した人だけの所要時間を全体の代表値にしない。未実施を0秒・失敗0件として集計しない。

## 判定と改善の優先順位

- 暫定の製品判断基準は、5人中4人以上が各タスクをH0で完了し、対象地域・制度条件・未確認事項の重大な取り違えが0件であること。これは今回の改善判断用で、母集団の成功率や統計的保証ではない。
- 同じ箇所の迷いが2人以上、または一人でも誤った対象・費用・安全の理解につながった場合は、原因と修正候補を優先して検討する。
- 5人未満の場合は `完了n / 実施n` と実人数を示し、5人基準達成と報告しない。タスク別・支援段階別・途中中止を併記し、テーマ別の少数結果で優劣を付けない。
- 仕様・出典の事実誤りが見つかった場合は、参加人数や件数にかかわらず訂正対象とする。表示の問題と、外部資料の停止や接続の問題は分けて記録する。
- 自動操作の成功は技術的導線の確認であり、実参加者の理解・所要時間・初回成功の証明にはしない。修正後の学習済み参加者の再試行も、別の初回利用とは数えない。

2026-10-23の検証対象は、本ブランチのPR作成前のローカル作業ビルド。自動操作はローカルの静的出力とAPI mockを使用し、公式資料を含む外部通信を遮断して実施した。原本リンクは適切な公式URLへの別タブ要求までを確認し、外部ページの正常表示・本文の理解は検証していない。全9経路で横方向のはみ出しとページ実行エラーはなかった。開発サーバーでも320／390／1440pxの同じ3経路を補助確認した。これら18経路の自動確認を、18人や実参加者の成功率として数えない。

[保存した操作検証結果](first-use-checks-2026-10-23.json)に、静的9経路、設定・停止・失敗系9ケース、区グリッドの追加結果と実施条件を残した。元のローカル結果を読み取り照合し、閲覧した人物名・具体的な外部資料URLは保存版から除外した。開発サーバーでの9経路は補助確認として区別する。再検証時は対象ビルドと結果を改めて記録する。これらはコード・データ・導線の検証であり、実参加者テストの代わりにはしない。

`/area/` の既存区グリッドと計測停止ページは、320／390／1280pxで追加確認し、地域表示→選択の2イベント、停止操作、横方向のはみ出し・実行エラーなしを確認した（[保存した検証結果](first-use-checks-2026-10-23.json)）。最終の区グリッド属性・公開説明文の変更後も、実装担当から静的build 1,486ページ、63件のfixture、typecheck・lint・差分検査の通過報告を受けた。

地図や他一覧からの直接流入まで、すべての入口を網羅した検証ではない。代表者・案件・資料へ直接進む操作も許容し、順次導線の計測に入らなかったことをユーザーの失敗とは判定しない。
