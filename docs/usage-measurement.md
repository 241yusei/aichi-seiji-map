# 利用状況計測の定義と検証

作成日：2026-10-23。

**2026-10-23のPR作成時は `enabled=false`。2026-10-30の本番反映依頼に合わせ、本番設定を有効にし、開発・Previewは無効を維持する。公開後の設定・配信状態は実応答で確認する。利用実績や保存成功をローカル検証から推測しない。ここで定義する数値は操作段階の集計だけを対象とし、実参加者テストは [first-use-study.md](first-use-study.md) で別に扱う。**

## 計測で答える範囲

どの操作段階まで進むイベントが観測されたかを、大きな単位で確認する。政治的関心・居住地・誰を調べたかを把握するためには使わない。

計測対象の地域選択は、地域pickerの選択欄、郵便番号からの解決、保存地域からの遷移と、`/area/` の既存区グリッド。地図や他一覧のリンクなど、すべての入口に前段が付くとは限らない。サイト全体の訪問・全導線を網羅する計測ではない。

地域・代表者・暮らしの案件・根拠資料は、それぞれ直接開くこともできる。今回の実装は同じタブの前段記録を使って順次導線を限定し、途中の段階への直接流入はその導線の件数へ含めない。それでも別タブ・別端末・別日を同一人物として結べず、匿名の件数だけから個人の一連の初回完了を証明することはできない。

技術契約は、同じサイトの `/api/usage` へ `POST {version:1,event}` のみを送信し、Cloudflare Analytics Engine の `blob1` に許可イベント名だけを書く構成。ブラウザ側は `keepalive`、`credentials: "omit"`、`referrerPolicy: "no-referrer"` を使う。サーバーでproduction条件と保存先のbindingを確認する。環境設定・SQL・料金・保持期間・公開前の有効化手順は [DEPLOY.md](../DEPLOY.md) を参照する。

## 扱う情報の境界

送信・アプリ側保存の対象は、許可された操作段階と、その段階別の集計に必要な最小項目に限る。実装では未知キーを拒否し、後から任意の文言を載せられる自由記述を設けない。

以下はイベントへ含めず、ダッシュボードの分類・絞り込み・例示データにも持ち込まない。

- 選んだ地域、住所、郵便番号、自治体コード、区・市町村slug
- 政治家・候補者・首長・政党・会派の名称やID
- テーマ名・争点ID、ページタイトル、閲覧URL、遷移先URL、検索語
- IPアドレス、利用者ID、セッションID、端末ID、Cookie ID、広告ID
- User-Agent、Referer、画面サイズ、自由記述、クライアントが取得する正確な操作時刻や一連の操作履歴

地域の明示保存は既存の `lib/region-preference.ts` が端末のlocalStorageで行う別機能であり、計測処理がその値を読んだり送信したりしてはいけない。テスト記録の匿名番号もイベントへ送信しない。

HTTPでは接続先の基盤がIPやリクエストヘッダーを受け取ることと、計測アプリがそれを記録することは別である。「通信にもIPが存在しない」とは説明しない。計測コードはリクエスト本文やヘッダーのログ出力、IP等による識別、プラットフォームログへの転記を行わない。Analytics Engineには基盤の受信時刻などの標準メタデータがあり、期間を区切った集計に使う。これはクライアントから送る操作時刻とは別であり、「時刻を一切保存しない」「完全匿名」とは説明しない。基盤側のログ・保持・課金・アカウント設定は、ローカルのコード検査だけでは確認済みにしない。

## 段階と件数

| 許可イベント | 発火の条件 | 前提となる段階 | この件数が意味しないこと |
|---|---|---|---|
| `region_step_viewed` | 地域を選ぶpickerが可視になった | なし | 初めて来た人・全訪問数 |
| `region_selected` | 有効な地域選択が行われ、遷移を開始した | `region_step_viewed` | どの地域を選んだか、遷移の完了 |
| `representative_viewed` | 選択後の個人ページが可視になった | `region_selected` | 氏名・層の理解、支持 |
| `living_topic_viewed` | 個人ページの後で暮らしブリーフの見出しが可視になった | `representative_viewed` | 読了、対象者であること、政策への賛否 |
| `source_reference_opened` | ブリーフ内の資料一覧へのショートカット、または `[出典n]` をクリックした | `living_topic_viewed` | 一次資料への外部到達、内容の理解 |
| `source_external_opened` | ブリーフにある一次資料の外部リンクをクリックした | `living_topic_viewed` | 外部ページの正常表示・読了・理解 |

各イベントはタブ内のsessionStorageの `torisetsu:journey:v1` に、段階の完了フラグ（許可されたイベント名の配列）だけを保存する。前段を確認し、そのフラグが維持されている間は当該段階を一度だけ送信する。人物・地域・テーマ・URLやユーザー／セッションを識別する値をsessionStorageの計測キーへ持たせない。同じタブで別の地域やテーマを開いても、その内容を分類せず当該段階は一度だけとする。

停止時は段階フラグを消す。停止後の再許可、sessionStorageの消去、タブの状態消失などにより、同じ人・同じタブでも最初の段階から再計数されることがある。ブラウザがタブを復元した場合は、以前のフラグが残って再計数されない場合もある。「タブを開いた数」「一訪問に一度」とは一致しない。

設定応答が来るまでの操作は、最大32個のイベント名だけをメモリ内で待機させる。有効と確認できた場合だけ順に送信判定し、無効・停止・DNT/GPCの場合は破棄する。設定取得は5秒でタイムアウトし、失敗時は観測できないが本体の操作を止めない。イベント名以外の入力値・URL・時刻はこの待機列へ含めない。

`source_reference_opened` は任意の枝で、`source_external_opened` の必須前段ではない。資料一覧を経由せず直接外部リンクへ進む操作もあるため、この二つの件数差を脱落人数と呼ばない。

見出しが可視になったことと本文を読み終えたこと、外部リンクをクリックしたことと移動先が正常表示されたことを区別する。送信の試行・重複防止用の記録は受信成功の証明ではない。同じタブの重複抑制があっても、別タブ・別端末・再訪を同一人物と識別しない。

### 分母と分子

集計期間を固定し、その期間で除外・受付条件を満たして保存された段階別件数を `C(イベント)` とする。Analytics Engineの集計には `SUM(_sample_interval)` を使う。サンプリングされた場合は補正推計値となり、保存行数や `COUNT(*)` と混同しない。送信を試みた件数とサーバーが受理・記録した件数も区別する。

| 指標 | 分母 | 分子 | 読み方と限界 |
|---|---|---|---|
| 段階別の集計件数 | なし | `C(当該イベント)` | 同一タブで一度送る段階イベントの集計値。サンプリング時は補正推計値。人数・利用セッション数とは呼ばない |
| 地域表示に対する段階件数比 | 同期間の `C(region_step_viewed)` | 同期間の `C(region_selected)`、`C(representative_viewed)`、`C(living_topic_viewed)`、または `C(source_external_opened)` | 順次導線の参考値。同一人・実際の初回利用者の完了率ではない。期間境界・欠測・別タブ・サンプリングで100%を超えても丸めず理由を確認 |
| 資料参照の内訳 | 同期間の `C(living_topic_viewed)` | 同期間の `C(source_reference_opened)` または `C(source_external_opened)` | 一覧／出典番号の操作と外部リンクの操作を別々に示す。両者の差は離脱者数ではない |
| 観察タスクの無支援完了 | そのタスクを実際に行った実参加者数 | H0で完了条件を満たした実参加者数 | 手動の観察記録でのみ算出。イベント数を分母・分子に使わない |

分母が0なら比率は `—（算出不可）` とし、0%にしない。集計期間、対象環境、集計単位、重複抑制、除外方式、欠測を数値と一緒に示す。未実施・未接続・閲覧制限等で数値を取得していない場合は0件と書かない。

## 集計にできないこと

- ユニーク利用者、新規利用者、実際の初回利用者、年齢・居住地・属性別の利用率
- 個人や端末をまたぐ順路、地域から出典までの一人ごとの完了、初回／再訪の識別。前段の完了フラグを使った制御は、利用者を識別するコホート分析とは異なる
- 読了、政策の理解、正誤判断、信頼、満足、投票行動への影響
- 全訪問者に対する代表性や、政治に関心の薄い人にも使えるという保証

これらは指標の名前を変えるだけで測れるようにはならない。必要な理解・迷い・完了は、固定シナリオの実参加者観察で別に確かめる。

## テスト・開発トラフィックの除外

- localhost、公開前プレビュー、CI、ヘッドレスブラウザ、AI操作、手動の実装確認、実参加者テストは、本番の通常利用集計へ送らない。接続先のサーバー側でも本番条件を限定する。
- 公開サイトを自動確認する場合は、最初のナビゲーションより前に除外を設定する。途中で除外しても、設定前の通信は取り消せない。
- DNTまたはGPCの停止指定がある環境では計測しない。フッターの「利用状況の計測」から、端末のlocalStorageに停止設定を保存して停止できる。停止設定はlocalStorageの `torisetsu:usage:off` の値 `1`。書込みできない場合も、そのタブが開いている間はメモリ内で停止を維持する。テストはこの設定を最初の操作前に適用する。UAやIPからテストを推定して除外する方式は採らない。
- テストでは送信処理をモックするか一時的なローカル受信先を使い、イベント形式・除外・重複抑制を検証する。本番の保存先を検証のために使わない。
- 計測除外と通常の地域保存を混同しない。除外設定の確認だけを目的に、保存地域や閲覧履歴を計測することはしない。

手動確認は対象サイトの `/usage/` を直接開き、「この端末で計測を停止する」を選び、停止表示を確認してからトップへ進む。この設定ページ自体に段階の表示イベントは配置していない。既に停止中またはDNT/GPC有効なら、その状態を確認する。自動確認はテストランナーのページ初期化処理で、対象OriginのlocalStorageへ次を設定してから最初のページを開く。既にサイト上で操作した後に設定して、最初から除外されていたとは扱わない。

```js
localStorage.setItem("torisetsu:usage:off", "1");
```

送信内容そのものを検証する試験だけは、停止を解除した使い捨て環境とモック受信先を使用する。本番datasetへ試験件数を書き込まない。試験後に本人の停止設定を勝手に解除しない。


## 欠測・偏りの記録

| 状態 | 記録する内容 | 避ける解釈 |
|---|---|---|
| JavaScript停止、ブラウザ拡張、ネットワーク遮断 | 計測できない訪問がある。取得率は不明 | イベントなし＝利用なし |
| 計測先未設定、未展開、サーバーエラー | 観測系が未稼働または一部欠測。設定・障害期間を別途確認 | 機能が不人気、利用者が0人 |
| 送信がページ移動・終了等で完了しない | 送信失敗・中断があり得る。受理前に成功とみなさない | 資料リンクを押す人はいない |
| 任意参加・同意・除外設定 | 観測対象は条件を満たす訪問だけ | 全利用者に同じ割合が当てはまる |
| サンプリングを行う場合 | 抽出単位・対象・確率・期間を数値に添える。未実装なら推定で補完しない | 一部観測値を説明なしに全訪問へ拡大 |
| タブ内の段階フラグ | 再読込・タブ復元・別タブ・保存消失・停止後の再許可で重複や欠落が変わる | 重複を抑えた件数＝ユニーク人数 |
| 小さい件数、公開初期、曜日・告知の偏り | 日々の変動と導入・告知の影響を含む | 小さな増減だけで改善効果や因果関係を断定 |
| 実参加者5人の便宜募集 | 記録はその5人とシナリオに限る | 全国の利用者の成功率・満足度 |

サンプリング、重複抑制、選択バイアス、通信による欠測は別の要因として書く。サンプリングをしていないことは、欠測や選択バイアスがないことを意味しない。
